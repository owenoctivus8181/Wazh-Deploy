
# wazuh-deploy

Ansible playbook that automates a full Wazuh all-in-one deployment — indexer, manager, and dashboard on a single host — including certificate generation/distribution, SELinux handling, Filebeat log shipping, firewall hardening, and a five-module detection config (FIM, SCA, rootcheck, vulnerability detection, log collection).

This exists because doing it by hand is error-prone: cert ownership per component, SELinux contexts, XML validation, and correctly formatting Filebeat's YAML are easy to get wrong manually. This playbook encodes all of that as idempotent tasks with built-in validation.

## What it does

- Generates TLS certificates via `wazuh-certs-tool.sh` (skipped if already generated)
- Installs and configures `wazuh-indexer`, `wazuh-manager`, `wazuh-dashboard`
- Distributes the correct cert/key pair to each component's own directory with correct ownership, permissions, and SELinux context
- Configures **Firewalld** to open the specific ports required for components to communicate
- Installs and configures **Filebeat** to ship Wazuh Manager and API logs to the Indexer
- Templates `ossec.conf` with FIM, rootcheck, SCA, vulnerability detection, and log collection enabled
- **Validates** the rendered XML config *before* writing it to disk (`validate: xmllint --noout %s`) — a broken config never reaches the live file
- **Validates** the Filebeat YAML configuration using `filebeat test config` before restarting the service
- Sets `vm.max_map_count` for the indexer (OpenSearch requirement)
- Fully idempotent — safe to re-run; a second run should show `changed=0`

## Requirements

- Target host: RHEL/Fedora family (uses `yum_repository`/`dnf`; adapt `roles/wazuh_indexer/tasks/main.yml` for Debian-based hosts)
- Ansible ≥ 2.15
- Collections:
```bash
  ansible-galaxy collection install ansible.posix community.general
```

· SSH access + passwordless sudo to the target host

· Minimum 4 GB RAM / 2 CPU on the target (indexer + manager + dashboard together are resource-heavy)

· Filebeat requires that the Indexer (port 9200) is accessible.

## Firewall Settings

To ensure the All-In-One deployment works out of the box, the playbook configures firewalld to allow the following ports. You can also manually open them using:

```bash
sudo firewall-cmd --permanent --add-port={1514/tcp,1514/udp,1515/tcp,55000/tcp,9200/tcp,443/tcp}
sudo firewall-cmd --reload
```

```markdown
| Port (TCP/UDP) | Component       | Purpose                                     |
| :------------- | :-------------- | :------------------------------------------ |
| 1514/TCP, UDP  | Wazuh Manager   | Agent communication                         |
| 1515/TCP       | Wazuh Manager   | Agent enrollment                            |
| 55000/TCP      | Wazuh Manager   | Wazuh API                                   |
| 9200/TCP       | Wazuh Indexer   | Filebeat / API traffic                      |
| 9300-9400/TCP  | Wazuh Indexer   | Internal cluster transport (single-node)    |
| 443/TCP        | Wazuh Dashboard | HTTPS Web interface                         |
```

## Setup

1. Edit inventory/hosts.ini with your target host's IP/user:

```ini
   [wazuh_aio]
   wazuh-server ansible_host=YOUR_IP ansible_user=YOUR_USER
```

2. Adjust group_vars/all.yml if you want a different Wazuh version or node naming.
3. Run:

```bash
   ansible-playbook site.yml
```

4. Get the dashboard admin password (generated by wazuh-certs-tool/install, check indexer security init) and log in at https://YOUR_IP.

## Filebeat Installation & Configuration

Filebeat is an essential component for a Wazuh AIO setup. It reads the Wazuh Manager's logs (alerts, API logs) and ships them to the Wazuh Indexer for indexing and storage.
How the Playbook Handles It:

· Installation: Installs Filebeat using the official Wazuh repository.

· Configuration: Templates /etc/filebeat/filebeat.yml pointing to the local Wazuh Indexer (default: https://localhost:9200).

· Modules: Automatically sets up the wazuh Filebeat module.

· Certs: Distributes the appropriate certificates to /etc/filebeat/certs/ for secure TLS communication.

· Validation: The playbook runs filebeat test config -c /etc/filebeat/filebeat.yml before restarting the service, ensuring a broken config (like a YAML indentation error) never breaks the service.

## Troubleshooting Filebeat

If Filebeat fails to start (often due to YAML formatting issues):

1. Test the config manually:
   ```bash
   sudo filebeat test config -c /etc/filebeat/filebeat.yml
   ```
   Expect to see Config OK.
   
3. Check the logs:
   ```bash
   sudo journalctl -u filebeat -n 50
   ```
   Note: The yaml: line 21: did not find expected key error is usually caused by missing spaces after colons (:), inconsistent indentation, or using tabs instead of spaces. Always use 2 spaces for indentation in YAML.

## Verifying idempotency

```bash
ansible-playbook site.yml

```

## Known limitations / next steps

· ossec.conf.j2 currently ships a minimal version of the five-module config — extend it with fuller FIM directory lists, custom SCA policies, and log source filters as needed

· No multi-node/cluster indexer support yet (single-node only)

· Firewall role is currently tuned for Firewalld (RHEL/Fedora); requires adjustment for UFW on Debian-based systems

· No Molecule test coverage yet (planned)
